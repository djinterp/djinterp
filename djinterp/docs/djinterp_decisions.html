1.1 Conventions every converted file follows

  • Banner. A fixed 80-column template: / plus 79 * opening, 79 * plus / closing, filename ending on column 80 of the title line, path:, link(s): and author(s): values starting on column 14, and created: / revised: values ending on column 80. The title tag is the file's top-level directory ([c], [env], [config], [net], ...).
  • Include guards. Derived mechanically from the path: DJINTERP_ + subsystem prefix + remaining directories + stem + _H, with #define GUARD 1 and #endif // GUARD.
  • Numbering. Sections are // N. NAME between 80-column //=== rules; subsections are // N.M Name followed by an 80-column //--- rule and zero blank lines; items are a // N.M.K marker line, then // NAME, then // category: description. Identifier tables use fourth-level // N.M.K.J entries. Two blank lines follow a section's description; one blank line separates items.
  • Tables of contents. Required, and generated from the body's markers, so the two always agree.
  • Includes. Grouped under category comments (// std, // djinterp, // platform, // openssl, ...), each with a trailing summary naming what is used from it, aligned where practical. Include what you use: a header that uses a macro includes the header that defines it, not a header that happens to pull it in.
  • Env headers.
    • Every detection macro is #ifndef-guarded, so builds can override it.
    • Each #endif closing an #ifdef/#ifndef names its symbol.
    • Multi-condition #ifs put one parenthesized condition per line, with the backslash at column 80.
    • C linkage uses #if D_ENV_LANG_USING_CPP + extern "C" {: env headers sit below djinterp.h, so D_EXTERN_C_BEGIN is unavailable to them.
  • Function comments. Doxygen contracts on header declarations (@brief, @param[in|out|in,out], @return except for void). Mechanism prose on definitions, in a /* block that opens with the function's name and carries no contract tags.
  • Verification. Every conversion was checked for identical behavior.
    • Preprocessor macro state (-dM) and token streams (-E) are compared between the old and new versions across targets (clang -target ...), languages, and configurations.
    • Stand-ins replace unavailable headers.
    • Strict builds use -Wall -Wextra -Werror -pedantic -Wshadow -Wconversion, plus -Wreserved-identifier -Wdocumentation on clang.

cli-taken 13. What the module holds

  • A. The module is self-contained: the window's code and, statically, the same core library and kit the program links; the program and the module meet only at a C interface of two structures and one exported function (d_cli_plugin_entry). For: works with every toolchain and runtime - MSVC's static runtime, MinGW, a renamed executable - with nothing exported from the program; the module is built with hidden symbols, so its copy never binds to the program's. Against: the core's code is in both files (on the order of a megabyte), though only one copy runs at a time.
  • B. The program exports its core and the module links against it (CMake's ENABLE_EXPORTS). For: no second copy. Against: on Windows every core function needs __declspec(dllexport), the module imports from the executable by its file name - so a renamed bitwisedom.exe cannot load it without a delay-load hook, which MinGW lacks - and an executable exports at most 65,535 symbols; on Linux the program is linked with -rdynamic.
  • C. The core as a shared library for both. For: conventional. Against: the command-line program is no longer one file.

The interface is the same under all three, so A can become B later without touching it.

Ruled (lane G; done): the owner's words: "Allow CFG control knobs and options that specify for either, allowing capabaility for either and giving the user the most options/control. Would that work?". The recommendation was: Confirm A, as taken: The module is self-contained. Settled 11-04: a build option between A (self-contained, the default) and C (the core as a shared library); no B (Windows: a renamed program cannot load its modules; MinGW has no delay-load hook); no run-time option, since linking is fixed at build.
