Known false-greens — re-verified 2026-08-25, all still false

Ten symbols are catalogued with a secondary_min but have no implementation. Verified against the filesystem, not the data:

  • <type_traits> — is_trivial, is_trivially_copyable, is_standard_layout, is_abstract, is_aggregate, has_virtual_destructor, has_unique_object_representations, is_scoped_enum. No file exists for any of the eight.
  • <compare> — three_way_comparable, three_way_comparable_with. The compare/compare umbrella includes two files that do not exist, so #include "re_std/cpp/compare/compare" fails to compile.

These are not merely a cataloguing problem. optional/optional_base.hpp uses re_std::is_trivially_copyable, so <optional> does not compile, and <ranges> fails through it. bit/bit_cast.hpp calls __is_trivially_copyable directly to work around the same gap — delete that local detection when the trait ships.

Mis-ordered namespace macros — four files

NS_ opens and NS_END closes are count-balanced but wrongly sequenced, so a plain open/close tally reports them clean. A running-depth check does not:

file defect
algorithm/sort.hpp stray NS_END at line 337
algorithm/stable_sort.hpp stray NS_END at line 354
string_view/char_traits.hpp stray NS_END at line 392
tuple/tuple.hpp stray NS_END at line 118

char_traits.hpp is the clearest case and shows the full consequence: NS_INTERNAL opens at line 65 with no enclosing NS_RESTD, so char_traits_base lands in ::internal; the stray NS_END at 392 emits a } at global scope; and the NS_RESTD at line 431 is never closed, leaving re_std open so every later include nests into re_std::re_std. The char_traits<char> and <wchar_t> specialisations therefore sit at global scope, which is exactly what the compiler reports.

The two algorithm files are the dangerous ones: <algorithm>'s umbrella compiles anyway, because a sibling header happens to leave a namespace open at the point they are included. They are correct only by include order.

Audit command (order-aware, catches what a tally misses):

python3 - <<'PY'
import glob, re, os
OPEN  = re.compile(r'^\s*(NS_RESTD|NS_INTERNAL|NS_RANGES|NS_CONCEPTS|NS_DJINTERP|D_NAMESPACE)\b')
CLOSE = re.compile(r'^\s*NS_END\b')
for f in sorted(glob.glob('re_std/**/*', recursive=True)):
    if not os.path.isfile(f): continue
    depth = 0
    for n, line in enumerate(open(f, errors='ignore'), 1):
        if OPEN.match(line):  depth += 1
        elif CLOSE.match(line):
            depth -= 1
            if depth < 0: print(f'{f}:{n} stray NS_END'); break
    else:
        if depth: print(f'{f} ends with depth {depth:+d}')
PY

Caveat on this audit

All compilation was done against a stand-in core/djinterp.hpp, since the corpus ships without the real one. The stub supplies the macro vocabulary the headers reference, derived from RE_STD_AGENT_README.html. The four namespace defects above are confirmed by static analysis and do not depend on the stub; the <expected> and <optional> failures are ordinary missing-declaration errors that do not either. Re-run against the real core header before acting.
