1. What 1.0 and 1.1 are

Semantic versioning, with three kinds of module. A stable module's public API is frozen at its release's RC1 and stays source-compatible through 1.x; the promises are claimed for it, and its gates run in CI. A preview module ships in the same release, builds on every ladder level, is documented and tested, and may change in a minor release; its README and the release notes say so. 1.1 is a minor release a month after 1.0: it keeps 1.0's stable API, makes stable the preview modules whose gates are green, and adds what December builds.

7. How the lanes work together

One base
Every lane works on the latest base-N from the restructured tree. From base-0 on, nobody works on the old layout, so the math lane's 42 shims and the stream lane's old paths retire with it.
Deliveries
One zip per delivery of the files changed or added, at their base-N paths, named <lane>_<yyyy.mm.dd>.zip, and a short handoff note: what is new, decisions with the lane's letter (A1, B1, ...; math keeps its S numbers), the checks run with their numbers, findings for other lanes, what is next.
Ownership
A lane edits only its own directories (section 5). A change that another lane's directory needs goes as a request in the handoff note, and lane A routes it. Shared files have one owner: dconfig.h, the CMake roots, .github/ and DECISIONS.md are A's; the message-code registry is E's.
Before delivering
The style check on every changed file; the ladders on the lane's units at every level with GCC and Clang, plain and testing; its DTest suites; ASan and UBSan over them. Lane A's CI runs the same checks on every base.
Decisions
A lane's decision stands unless the owner overrules it by the next window (the math lane's rule, made general). Lane A merges the registers into docs/DECISIONS.md weekly.
Merges
The owner merges in the windows. Lane A's merge helper lays the zips over base-N in order, lists any file two zips touch, and runs the gates, so a window is mostly unzipping and reading one report.
Continuity
Accounts hit usage limits and sessions reset, so each chunk is sized to end in a delivery, and each starts from the lane's last handoff note and its brief.
Between releases
From 1.0's feature freeze, a lane whose 1.0 work is done may write its 1.1 design notes and prototypes; nothing for 1.1 is merged before v1.0.0 is tagged. December starts from the v1.0.0 tag with the same windows. A fix to 1.0 also goes into 1.1; a 1.0.1 is made only under ruling 15.
Changing lanes
In December net and db move from lane H to lane C, and dawk and the scripts to lane D. Lane H writes a handoff note for each by Friday 11-27, as a lane does at the end of any chunk, and lanes C and D start from those notes on Tuesday 12-01.

8. Tests: the largest share

Today
2,188 test sources. 399 of 1,024 library headers (39%; the generated macro tables aside) are included directly by some test. Of the 1,309 C++ test units, 850 compile at C++17 and C++20; 416 fail at both (the test framework's API mid-rewrite, includes into a core/ folder the tree no longer has); 12 break at C++20; 31 compile only at C++20. The C test runner has never compiled.
The 1.0 target
The floors of ruling 6: every public header of a stable module has a DTest 2.0 suite that passes at every ladder level on the three required platforms; line coverage of at least 80% in the core, 60% elsewhere stable; a parity test for every C++ face; smoke suites for preview.
The 1.1 target
Floors raised to 85% line coverage in the core and 70% elsewhere stable; every module 1.1 makes stable held to 1.0's floors; a planted-fault trial over the core modules, the math lane's method (plant one fault at a time and count what the suites catch), catching at least 90%.
Who
B: roots, env, re_std, memory, sync, filesys. C: container, functional, meta, paradigm, binary. D: text, util, the stream. E: option, event, desc, log. F: parse. G: math. H: net, db, dawk. Every lane tests its own new code as it writes it. In December, B keeps the floors, runs the trial and writes the suites for parse's outer layers, parsegen and vparse; C tests net and db, D dawk, E desc and the log, F the adapters, H the interpreter.
Order
First the 416 broken units and tests/unintegrated, converted; then untested stable headers by risk (allocation, parsing and I/O first); then coverage gaps.
The C++20 breaks
Eight of the 12 are one defect: event/event_handler.hpp and paradigm/publisher/publisher.hpp both declare a concept djinterp::handler_for, with different parameters, so a unit that includes both stops compiling at C++20 (lanes C and E). Three are the test-option shape (lane B); one is a test that reads an undefined macro.
